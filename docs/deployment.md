# Deploy to your Cloudflare account

The workflow is `.github/workflows/cloudflare.yml`. It runs tests, TypeScript, both build targets, and a Wrangler upload dry run on pull requests and pushes. Deployment runs only on `main`, after checks pass, when explicitly enabled below. It serializes deployments and applies committed D1 migrations before uploading the Worker.

## GitHub configuration

Configure these in `wyaapp/app` (repository settings, or the `cloudflare-production` environment, except the enable switch which must be a repository variable):

| Kind | Name | Value |
| --- | --- | --- |
| Secret | `CLOUDFLARE_API_TOKEN` | Dedicated deployment token with Workers Scripts Edit and D1 Edit on the intended account |
| Secret | `CLOUDFLARE_ACCOUNT_ID` | Target Cloudflare account ID |
| Variable | `CLOUDFLARE_D1_DATABASE_ID` | UUID of the `wya-im` D1 database |
| Repository variable | `CLOUDFLARE_DEPLOY_ENABLED` | `true` after the other values are configured |

Do not use the Global API Key. The deployment token has no DNS or billing permissions. A token with account-level Workers/D1 permissions can affect other resources in that account; keep it restricted to this repository and rotate before expiry.

After creating D1, configure its UUID, enable deployment, and run the workflow manually or push to `main`. Check both jobs in Actions. The generated config lives in ignored `.cloudflare/`; the actual Worker upload uses `dist/server/wrangler.json` generated by the Cloudflare Vite plugin.

## Local use

Store the same three Cloudflare values in an ignored `.env.cloudflare.local` file with permissions `0600`. Never commit or print the token. With Node 22+, load that file without putting the secret in command arguments:

```sh
node --env-file=.env.cloudflare.local scripts/build-cloudflare.mjs
node --env-file=.env.cloudflare.local scripts/check-cloudflare-deploy.mjs
node --env-file=.env.cloudflare.local node_modules/wrangler/bin/wrangler.js d1 migrations apply DB --remote --config .cloudflare/wrangler.json
node --env-file=.env.cloudflare.local node_modules/wrangler/bin/wrangler.js deploy --config dist/server/wrangler.json
```

For a build-only check without credentials, run `npm run build:cloudflare -- --check`. Its placeholder database ID must never be deployed; the production validator rejects it.

## Public launch is separate

This standalone target currently has `workers_dev: false`, `preview_urls: false`, and no routes. Account and MCP endpoints return 503 because the Sites authentication gateway is not available in your account. The working Sites preview remains the usable version while independent sessions, OAuth account linking, profile migration, and domain routing are implemented. See [architecture.md](architecture.md).

Database migrations are applied before the new Worker. Keep migrations backward-compatible with the previous deployed version; a Worker rollback does not undo SQL migrations. Review destructive schema changes separately.

References: [Cloudflare GitHub Actions deployment](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/), [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/).
